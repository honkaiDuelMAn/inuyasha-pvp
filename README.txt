웹 버전 1.1.0: public/direct.html / GitHub Pages
별도 연결 서버 없이 전체 초대·응답 코드로 브라우저끼리 연결합니다.
서로 다른 인터넷 회선에서는 연결이 실패할 수 있습니다. 자세한 안내: README.md
아래는 기존 Windows 호스트 프로그램 방식입니다.

이누야샤 데몬 토너먼트 · 원본 리소스 1대1 PvP

버전 1.0.1: PvP 경기 시작 때 타이틀/직전 승패 음악이 계속 재생되던 문제를 수정했습니다.
이미 이전 버전을 사용한다면 public/game/pvp-bridge.swf만 새 파일로 덮어쓰고
양쪽 브라우저를 새로고침하여 새 경기를 시작해도 됩니다.

시작하기
1. ZIP을 전부 압축 해제합니다. 호스트 PC에서 '호스트-실행.cmd'를 실행합니다.
2. Chrome 또는 Edge에서 http://localhost:8787 을 엽니다. '방 만들기'를 누릅니다.
3. 호스트가 추가카드를 0~3장으로 설정합니다.
4. 게임 화면의 PLAY → NORMAL 또는 HARD → 원하는 캐릭터를 선택합니다.
5. 화면의 서버 주소와 방 코드를 상대에게 전달합니다. 상대는 자기 PC의 브라우저에서
   해당 서버 주소를 열고 방 코드로 참가합니다. 초대 링크는 방 코드를 자동으로 채웁니다.
6. 양쪽 모두 게임 화면에서 캐릭터를 고른 후 바깥쪽 '준비 완료'를 누릅니다.
7. 원본처럼 행동 카드 3장을 선택하고 CONTINUE를 누릅니다.
   양쪽이 제출해야 전투가 시작됩니다. 상대 카드가 먼저 공개되지는 않습니다.
8. 전투 애니메이션 뒤 NEXT ROUND를 눌러 진행합니다. 양쪽이 끝내야 다음 라운드가 열립니다.
9. 승패가 결정되면 양쪽이 '캐릭터 다시 선택'을 누릅니다. 같은 방에서 각자 새 캐릭터를
   골라 재대전할 수 있습니다. 호스트는 다음 경기의 추가카드 수를 바꿀 수 있습니다.

접속 주소
- 호스트의 실행 창을 켜 두세요. 닫으면 모든 방이 종료됩니다.
- 상대는 http://localhost:8787 로 접속하면 안 됩니다. localhost는 상대 자신의 PC입니다.
- 같은 공유기/네트워크에서는 호스트의 화면에 표시되는 IPv4 주소로 접속합니다.
- 다른 집/네트워크에서는 호스트 PC에 도달할 수 있는 주소가 필요합니다.
  같은 가상 LAN/VPN을 이용하거나, 호스트 공유기에서 TCP 8787을 호스트 PC로 전달합니다.
  VPN을 쓰면 주소란에서 그 VPN의 호스트 IP를 선택하거나 직접 입력하세요.
- Windows가 실행 파일의 네트워크 접근을 물으면 대전에 사용할 네트워크에서 허용합니다.
  연결이 안 되면 상대 PC에서 서버 주소 자체가 열리는지 먼저 확인하세요.
- 실제 외부 PC/공유기의 연결 상태는 자동으로 설정하지 않습니다.
- 포트가 사용 중이면 기존 실행 창을 닫습니다. 다른 포트가 필요하면 실행 전
  PVP_PORT 환경 변수에 포트 번호를 설정할 수 있습니다.
- 호스트가 나가면 방이 닫힙니다. 2P가 나가면 1P는 새 참가자를 받을 수 있습니다.
  끊겼던 사람은 페이지를 새로 열어 참가하세요. 진행 중 경기의 재접속 복원은 없습니다.

추가카드 규칙
- 0장: 추가카드를 뽑지 않습니다. 카드 추첨 난수도 호출하지 않습니다.
- 1~3장: 경기 시작 때 중복 없이 무작위로 뽑은 같은 목록을 양쪽에 지급합니다.
  매 라운드 다시 뽑지 않습니다. 재대전에서는 새로 뽑습니다.
- 원본 캐릭터별 사용 제한을 유지하며, 두 캐릭터 모두 사용할 수 있는 추가카드 중에서
  뽑습니다. 공통 5종은 완전방어, 회복, 금강, 오른쪽 두 칸 이동, 왼쪽 두 칸 이동입니다.
  두 캐릭터의 소환 카드가 같으면 해당 소환 카드도 추첨 대상입니다.
  예: 이누야샤/가영/미륵끼리는 싯포, 카구라/나락끼리는 요괴가 추가됩니다.
  같은 캐릭터끼리는 그 캐릭터의 원래 추가카드 6종이 대상입니다.
- 금강을 뽑으면 양쪽 모두 금강을, 오른쪽 두 칸을 뽑으면 양쪽 모두 같은 이동 카드를 받습니다.
- NORMAL/HARD 선택 화면은 원본대로 남아 있습니다. PvP에서는 양쪽 모두 사람이므로
  원본의 AI 난이도가 대전에 영향을 주지 않습니다.

원본 보존
- '원본 게임' 버튼으로 수정하지 않은 싱글플레이 SWF를 실행할 수 있습니다.
- 기존 그림, 소리, 카드, 캐릭터, 전투 판정과 애니메이션을 재사용합니다.
- 원본 게임 SWF의 1,459개 태그는 모두 바이트 단위로 유지했습니다.
  PvP용 파일에는 모드 연결 코드 한 개만 추가하고, 별도 통신 모듈을 불러옵니다.
- 원본 게임과 캐릭터/소환수 SWF 12개는 원본 SHA-256과 일치합니다.
- Flash 실행은 함께 포함한 Ruffle을 이용합니다. Flash 플러그인이나 Node 설치는 필요 없습니다.
  에뮬레이터와 예전 Flash Player 사이의 모든 세부 동작이 동일하다고 보장하지는 않습니다.
- 테스트 환경에서는 원본 설명 창의 내용이 비어 보였습니다.
  창 오른쪽 위 X로 닫고 진행하세요. PvP 조작 안내는 이 문서와 바깥 게임 화면에 있습니다.

파일과 개발
- public/game: 원본, PvP SWF, 캐릭터 리소스
- public/ruffle: Ruffle 0.6.0 로컬 실행 파일과 라이선스
- server: 방/동기화 서버, 원본 카드 정의
- flash: 추가한 연결 코드 원본
- runtime: Windows x64 Node.js 24.19.0 실행 파일과 라이선스
- node_modules/ws: WebSocket 라이브러리 8.22.0과 라이선스
- tests: 방 규칙, HTTP/WebSocket, 원본 보존, 실제 브라우저 대전 검증
- tools/build.py: JPEXS로 추가 모듈을 빌드하는 스크립트

검증 명령 (개발자용)
runtime\node.exe --test tests/*.test.mjs
python tests/build_test.py
브라우저 검증은 Playwright 설치 후 서버를 켜고 실행합니다:
  node tests/browser.cjs
  node tests/bonus-browser.cjs
  필요하면 CHROME_PATH, PLAYWRIGHT_PATH, PVP_ORIGIN을 지정합니다.
전체 경기를 실제 원본 게임 화면의 클릭으로 진행합니다. 일부 판정은 검증 로그에 기록됩니다.
추가카드 검증은 별도 테스트 서버를 자동으로 시작해 1장/2장과 금강 조합을 확인합니다.
음악 검증은 아래 관측용 모듈을 먼저 빌드한 뒤 실행합니다(Java와 JPEXS 필요):
  python tools/audio_probe.py --java java.exe경로 --ffdec ffdec.jar경로
  node tests/audio-browser.cjs
관측용 모듈은 테스트 브라우저에만 주입하며 실제 배포 게임에는 포함하지 않습니다.

다시 빌드하기 (개발자용)
Python, Java, JPEXS FFDec가 필요합니다. 배포본 실행에는 필요 없습니다.
python tools/build.py --original 원본SWF폴더 --java java.exe경로 --ffdec ffdec.jar경로
다운로드 원본은 빌드 입력으로만 읽으며 덮어쓰지 않습니다.
