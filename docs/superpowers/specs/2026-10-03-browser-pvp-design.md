# Browser-hosted PvP without a connection server

The user wants visitors to one GitHub Pages address to play the existing original-resource game. The owner's PC may be off. The visitor creating a room hosts it. No external signaling, STUN, TURN, WebSocket, database, or room service is allowed. GitHub Pages only serves static files.

Use manual WebRTC offer/answer exchange and an ordered reliable data channel with `iceServers: []`. The host sends a complete invitation code privately; the guest returns a complete response code. These are connection descriptions, not globally searchable six-digit room IDs. An ID labels the room but cannot locate another browser without exchanging descriptions. Show this distinction in the UI. Some routed/NAT networks cannot connect under these constraints; explicitly show this before creation and on timeout. Do not claim arbitrary internet connectivity. The local two-browser probe passed but does not establish two-PC internet reachability.

Move the existing room rules and original card catalog into a browser-compatible module, re-export from the Node server, and run RoomService in the host browser. Keep all original Flash assets, callbacks, combat, audio fix, card compatibility, sealed guest input, 0–3 shared bonuses, animation barrier, and post-match reselection. Host remains trusted as in the existing implementation.

Keep the existing Node package and index functional. Add a separate static direct entry (`direct.html`, deployed as Pages index) with no API requests. Adapt the shared app through a transport interface. Asset URLs must resolve relative to the deployment directory. No telemetry, hosted libraries, external fonts or connection servers.

Codes carry version, kind, session nonce, room ID and completed SDP; validate length, schema, offer/answer kind and matching session before application. Never interpret pasted data as script or HTML. Stale answers and duplicate application fail safely. Leaving/disconnecting resets the host's room. A new invitation is required for a replacement guest. Closing the host browser ends the match. Pending operations are canceled on leave; connection establishment has a finite timeout and a clear failure.

Publish a new public `honkaiDuelMAn/inuyasha-pvp` repository and Pages deployment, within the user's requested publication scope. Do not modify existing unrelated repositories. Include self-hosted Ruffle and original resource attribution. Before publication prove static nested-path loading, two independent browser connections, original combat and rematch, disconnect/replacement, failed-code recovery and no outgoing connection-service requests. Verify the actual Pages URL after deployment. Clearly report that real external-PC connectivity remains environment-dependent and has not been tested here.
