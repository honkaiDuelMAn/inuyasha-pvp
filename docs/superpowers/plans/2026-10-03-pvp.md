# InuYasha PvP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add original-resource two-PC PvP, shared 0–3 bonus cards, and character reselection after each match.
**Architecture:** Append AVM1 bridge actions after original initialization, preserving original SWF tags. A local Node WebSocket room service synchronizes original Flash engines in two browser clients running bundled Ruffle.
**Tech Stack:** Node 24, ws, Ruffle, AVM1 ActionScript, Python SWF builder, JPEXS compiler.
**Spec:** ../specs/2026-10-03-pvp-design.md

## Global Constraints
- Preserve all original SWF tags byte for byte; original mode loads unmodified SWF.
- 2 seats, host seat 0; bonus count exactly 0–3; no RNG when 0.
- Draw unique original cards compatible with both characters once per match.
- Original 3 distinct moves, original energy validation and combat.
- No public hosting, firewall changes, or account connections.

## Review Focus
- Invalid move IDs / over-budget energy / missing payload fields must not crash or advance a room.
- Same-character selections must have independent player state.
- One disconnected player must not leave a permanently waiting battle.
- Old/repeated messages must not reveal cards or restart animation.
- Runtime readiness, slow asset load, and different animation speeds must synchronize correctly.
