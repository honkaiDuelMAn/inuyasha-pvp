# 이누야샤 데몬 토너먼트 · 1대1 PvP

원본 Flash 게임을 Ruffle로 실행하며, 친구와 1대1 대전할 수 있습니다.

웹 주소: https://honkaiDuelMAn.github.io/inuyasha-pvp/

## 방 채팅 (1.2.5)

게임 오른쪽에서 같은 방의 1P·2P끼리 실시간으로 대화할 수 있습니다. 화면이 좁으면 채팅창은 게임 아래에 표시합니다. 한글·영어·숫자를 입력하고 Enter 또는 **전송**으로 보냅니다. 한글 조합 중 Enter는 전송하지 않습니다.

채팅은 연결된 기존 WebRTC 데이터 채널을 사용합니다. 초대·응답 링크와 QR, 현재 STUN 설정, 방·전투 판정과 카드 설정은 그대로이며 채팅 서버나 별도 연결을 추가하지 않았습니다. 경기 중·승패 화면·재대전 준비에도 대화할 수 있습니다.

한 메시지는 최대 500자이며 최근 200개 메시지를 각 브라우저에서 표시합니다. 서버나 파일에 대화를 저장하지 않고 새 참가자에게 이전 대화를 보내지 않습니다. 같은 방의 재대전에서는 대화를 유지하고, 방을 나가거나 연결이 종료되면 해당 브라우저의 대화를 지웁니다.

적용하려면 양쪽 모두 현재 경기를 마친 뒤 웹페이지를 새로고침하고 새 초대·응답 링크로 연결하세요.

## 웹에서 친구와 대전하기

1. 호스트가 웹페이지에서 **방 만들기**를 누릅니다.
2. **초대 링크 복사** 또는 **공유하기**로 친구에게 링크를 보내거나, 화면의 QR을 보여줍니다. QR 이미지를 저장해 보내도 됩니다.
3. 참가자는 링크를 열거나 휴대폰 카메라로 QR을 스캔합니다. 참가 절차가 자동으로 시작되고 **응답 링크**와 QR이 만들어집니다. 참가자는 응답 링크를 3분 안에 호스트에게 개인적으로 보냅니다.
4. 호스트는 **원래 방 탭을 계속 열어 둔 채**, 방을 만든 **같은 브라우저**에서 응답 링크를 엽니다. 기존 대기방에 자동 전달됩니다. 방 탭으로 돌아가 연결을 기다리세요. 다른 브라우저에서 열었거나 자동 전달이 안 되면 원래 방의 응답 입력란에 링크를 붙여 넣고 **응답 적용 · 연결**을 누릅니다.
5. 각자 게임 화면에서 PLAY → NORMAL 또는 HARD → 캐릭터 선택 후 **준비 완료**를 누릅니다.
6. 경기 종료 후 양쪽이 **캐릭터 다시 선택**을 누르면 같은 연결로 재대전합니다.

방을 만든 사람의 브라우저가 방과 대전을 관리합니다. 이 사이트를 배포한 사람의 PC는 꺼져 있어도 됩니다. 호스트가 페이지를 닫으면 해당 방은 종료됩니다.

## 링크·QR 공유 (1.2.0)

긴 코드를 읽거나 직접 입력할 필요 없이 링크와 QR을 한 번씩 교환합니다. **참가자의 응답 링크 전달은 필요합니다.** 초대 링크만 열어 호스트까지 자동으로 연결되는 방식은 아닙니다. 초대 링크는 주소 뒤 `#invite=`, 응답 링크는 `#answer=`에 연결 정보를 담습니다. 이 부분은 웹 서버에 요청되지 않으며, QR은 브라우저에서 생성합니다. 외부 QR 생성 서비스를 사용하지 않습니다.

호스트·참가자 모두 연결 중인 게임 탭을 닫거나 새로고침하지 마세요. 응답 전달 완료 화면의 별도 탭은 닫아도 됩니다. 링크를 연 뒤 주소에서 연결 정보를 지우므로 페이지를 새로고침하면 자동 참가를 반복하지 않습니다. 재접속하려면 새 초대를 교환하세요.

휴대폰 크기의 화면과 터치 입력으로 캐릭터·카드 선택 및 한 라운드를 검증했습니다. 실제 휴대폰 카메라와 모든 기종을 시험하지는 못했습니다. 연결 후 휴대폰에서도 원본 게임 화면을 터치해 조작합니다. 기존 IY1/IY2 코드 입력은 **기존 연결 코드 보기**에 남아 있습니다.

안드로이드와 iOS도 방을 만들 수 있습니다. 실제 갤럭시 S21+ 5G에서는 외부 후보(srflx)가 생성됐지만 Chrome이 ICE `complete`를 보내지 않아 시간 초과가 발생했습니다. 웹 1.2.4부터는 외부 후보가 1.5초 동안 안정되면 `complete`를 기다리지 않고 링크를 생성합니다. 링크를 만드는 동안에는 화면을 끄거나 다른 앱으로 이동하지 마세요.

## 짧아진 연결 코드 (1.1.1)

새 초대·응답 코드는 `IY2-`로 시작합니다. 연결 정보를 손실 없이 압축합니다. 현재 실제 Chrome 검사에서는 STUN 후보가 포함된 초대가 약 1,146자 → 514자, 응답이 약 964자 → 330자로 줄었습니다. 후보 수와 네트워크에 따라 실제 길이는 달라집니다. 페이지를 새로고침한 뒤 방을 만들면 적용됩니다.

기존 `IY1-` 코드도 입력할 수 있습니다. 기존 긴 초대에 참가하면 이전 호스트가 읽을 수 있는 긴 응답을 돌려줍니다. 양쪽이 페이지를 새로고침하면 짧은 코드를 사용합니다. 초대·응답 교환 순서는 그대로입니다.

## 연결 범위

GitHub Pages는 게임 파일만 제공합니다. 게임은 별도 방 서버나 신호 교환 서버를 사용하지 않으며, 두 사람이 초대·응답 링크 또는 코드를 직접 전달해 연결 정보를 교환합니다. WebRTC는 `stun.cloudflare.com:3478` 공개 STUN을 사용해 직접 연결 가능한 외부 주소를 찾습니다. STUN은 게임 데이터를 중계하지 않으며 TURN 중계 서버는 설정하지 않았습니다. 6자리 방 번호만으로 다른 브라우저를 찾을 수는 없습니다.

**서로 다른 인터넷 회선의 연결 성공률을 높이기 위해 STUN을 사용하지만, 대칭형 NAT·CGNAT·UDP 차단·엄격한 방화벽에서는 직접 연결이 실패할 수 있습니다. 모든 네트워크에서 접속을 보장하지 않습니다.** 연결이 안 되면 VPN을 끄거나 한쪽 네트워크를 휴대폰 핫스팟으로 바꾼 뒤 취소하고 새 초대·응답 링크를 교환하세요. TURN 중계를 사용하지 않으므로 공유기 차단을 우회할 수 없는 조합도 있습니다.

두 개의 독립된 로컬 브라우저와 실제 Pages 주소에서 연결 및 원본 전투를 검증합니다. 다른 외부 PC 두 대 사이의 연결은 이 환경에서 검증하지 못했습니다.

## 원격 직접 연결 개선 (웹 1.2.2)

- 기존 **초대 링크 → 응답 링크** 교환, QR, 호스트 권위형 방 규칙과 게임 동기화 방식은 그대로입니다.
- WebRTC ICE 설정에 Cloudflare 공개 STUN을 추가해 서로 다른 공유기 뒤에서도 외부 주소 후보를 만들 수 있게 했습니다.
- `turn:`/`turns:` 중계 주소와 인증 정보는 설정하지 않았습니다. 게임 데이터는 연결된 두 브라우저 사이에서 직접 전송됩니다.

## 모바일 방 만들기 개선 (웹 1.2.3)

- 모바일 데이터에서 ICE 후보 수집이 10초를 넘을 때 초대 링크 생성이 조기에 실패하던 제한을 30초로 늘렸습니다.
- 링크 생성 화면에 모바일 데이터에서는 최대 30초가 걸릴 수 있다는 안내를 표시합니다.
- 연결 방식, STUN 주소, TURN 미사용, 초대·응답 링크 교환 순서는 변경하지 않았습니다.

## 갤럭시 5G ICE 완료 신호 미도착 수정 (웹 1.2.4)

- 실제 갤럭시 S21+ 5G 진단에서 Cloudflare UDP 3478과 Google UDP 19302 모두 `host 1 + srflx 1` 후보를 만들었지만, 12초 동안 ICE `complete` 신호는 오지 않았습니다.
- 원인은 STUN 실패가 아니라 사용할 수 있는 외부 후보가 이미 있는데도 `complete`만 기다리던 링크 생성 조건이었습니다.
- 이제 `srflx` 후보가 나온 뒤 1.5초 동안 새 후보가 없으면 현재 SDP로 링크를 생성합니다. 이미 후보가 SDP에 들어온 뒤 리스너가 등록되는 경우도 처리합니다.
- 30초 제한은 외부 후보도 없고 `complete`도 오지 않는 경우의 최종 안전 제한으로만 남습니다. STUN 주소와 TURN 미사용 정책은 그대로입니다.

## 게임 규칙

- 호스트가 **공통카드 0~5장**, 원하는 공통카드 **밴**, 캐릭터 **전용카드 ON/OFF**를 경기 전에 설정합니다. 설정을 바꾸면 양쪽 준비가 해제됩니다.
- 공통카드는 더블 레프트, 더블 라이트, 치유, 완벽방어, 금강의 5종입니다. 밴하지 않은 카드 중 중복 없이 추첨하여 양쪽에 같은 목록을 지급합니다. 0장이면 추첨 난수를 호출하지 않습니다.
- 밴한 종류만큼 최대 장수가 줄고 현재 장수가 최대를 넘으면 자동으로 줄어듭니다. 밴을 해제해도 선택한 장수는 유지합니다. 공통카드는 경기마다 한 번만 뽑고 재대전 때 다시 뽑습니다.
- 전용카드 ON이면 공통카드와 별도로 각 캐릭터의 소환 카드 1장을 지급합니다. 이누야샤·가영·미륵은 싯포, 셋쇼마루는 자켄, 산고는 키라라, 카구라·나락은 요괴, 코우가는 늑대입니다. 기본 설정은 OFF이며, 공통카드가 0장이어도 전용카드는 지급할 수 있습니다.
- 공통 5장과 전용 1장을 모두 표시하고 선택할 수 있습니다. 한 라운드에 행동 카드 3장을 고르는 규칙은 그대로입니다. 같은 연결의 재대전에서는 설정을 유지하고 새 캐릭터의 전용카드를 지급합니다.
- 원본 캐릭터, 행동 카드, 전투 판정과 애니메이션을 사용합니다. 양쪽의 판정이 다르면 대전을 종료합니다.
- 대전 중 타이틀 음악은 원본 대전 진입 방식에 맞춰 정지합니다.

## 게임 조정 (웹 1.2.1)

로컬 게임 조정본 1.0.2의 산고·카드 설정만 웹 버전에 반영했습니다. **초대 링크 → 응답 링크 교환, QR, 직접 연결 방식은 1.2.0 그대로입니다.** 별도 호스트 프로그램이나 사용자가 운영할 연결 서버를 요구하지 않습니다.

산고 **Secret Sword**는 위력 15 → **25**, 소비 EN 25 → **15**이며 카드 숫자도 일치합니다. **Poison Powder**는 잘못 표시되던 카드 EN 15를 **20**으로 고쳤으며 실제 소비 EN 20과 위력 30은 그대로입니다. 산고 수정은 원본 게임 버튼으로 실행하는 싱글플레이에도 적용됩니다. 나머지 원본 태그 1,456개와 캐릭터·소환수 SWF 11개는 유지했습니다.

업데이트 후 두 사람 모두 페이지를 새로고침하고 새 초대를 교환하세요. 이전 게임 파일을 불러온 탭과 새 버전 탭을 섞어 사용하지 마세요.

## 소스와 실행

`public/direct.html`은 서버 없는 웹 버전입니다. `python tools/pages.py 대상폴더`로 정적 배포 파일을 만듭니다. `file://`로 직접 여는 대신 HTTPS 정적 호스팅 또는 개발용 localhost 웹서버를 사용하세요. GitHub Actions가 `pvp` 브랜치의 정적 파일을 Pages로 배포합니다.

기존 Windows 호스트 프로그램/Node 버전은 `public/index.html`을 계속 사용합니다. 해당 방식은 호스트 프로그램 실행이 필요합니다. 이전 배포 폴더와 ZIP은 별도로 보존했습니다.

구성요소 출처와 라이선스는 [THIRD-PARTY.txt](THIRD-PARTY.txt)를 참고하세요. 게임 리소스의 저작권은 원권리자에게 있습니다.
