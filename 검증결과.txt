이누야샤 PvP 검증 기록 · 2026-10-03

1.0.1 음악 수정
- 원본 싱글플레이는 대전 시작 화면에서 themeSong과 youDie 트랙을 정지합니다.
  PvP는 이 화면을 건너뛰어 음악 정지도 누락되어 있었습니다.
- PvP 경기 시작에 원본과 같은 두 트랙 정지 처리를 추가했습니다.
  효과음과 전투 음악은 원본 방식으로 유지합니다.
- 실제 두 브라우저에서 원본 Sound 객체를 관측한 회귀 테스트가 수정 전 실패했습니다.
  양쪽 타이틀 트랙이 계속 재생 중이고 정지 호출이 0번인 것을 확인했습니다.
  수정 후 양쪽 트랙 정지, 실제 Sound 재생 위치가 더 진행하지 않는 것,
  원본 전투 효과음·다음 라운드 진행을 확인했습니다.

구현
- 원본 Flash 6 게임을 유지하고 Ruffle로 실행합니다.
- 별도 Flash 8 통신 모듈과 Node WebSocket 방 서버를 추가했습니다.
- 1P 방 생성 / 2P 참가, 양쪽 사람 입력, 상대 카드 비공개 제출,
  원본 전투 판정과 애니메이션, 경기 뒤 캐릭터 재선택을 구현했습니다.
- 호스트 0~3장 설정, 동일한 공통 추가카드 목록, 0장일 때 추첨 생략을 구현했습니다.
- Downloads의 제공 원본은 수정하지 않았습니다.

확인한 증거
- Node 규칙/실제 HTTP·WebSocket·Windows 실행기 테스트: 21개 모두 통과.
  64개 캐릭터 조합 × 추가카드 1~3장, 0장 난수 호출 금지, 호스트 권한,
  2인 제한, 비공개 입력, 이전 입력 거절, 판정 불일치 시 종료, 재대전·연결 종료 포함.
- Python 원본 보존 테스트: 3개 모두 통과.
  원본 SWF 12개 SHA-256 일치, 원본 1,459개 태그 바이트 일치,
  추가된 태그 정확히 한 개, 게임 Flash 6 버전 유지와 별도 Flash 8 모듈 확인.
- 실제 Chrome의 독립된 두 브라우저에서 원본 화면을 클릭하며 대전했습니다.
  이누야샤 vs 가영, 같은 추가카드 3장, 6라운드 후 1P 승리.
  각 라운드의 체력/기력/위치/승패가 양쪽에서 일치했습니다.
- 종료 후 캐릭터 재선택, 이누야샤 vs 이누야샤, 추가카드 0장으로 재시작.
  원본 시작 체력·기력으로 초기화되고 독립적으로 이동하며 다음 라운드로 진행했습니다.
- 준비 완료 뒤 선택 화면 재개 시 준비 해제, 거절된 카드 제출 뒤 원본 선택 화면 복원,
  전투 도중 2P 이탈 뒤 새 참가자와 다음 경기 시작을 실제 브라우저에서 확인했습니다.
- 별도 실제 브라우저 대전에서 추가카드 1장/2장도 확인했습니다.
  1장 금강을 받은 가영이 '기력 회복 → 금강 → 영력'을 원본 화면에서 선택·제출하고,
  양쪽 판정 일치와 다음 라운드 진행을 확인했습니다. 2장에서는 두 칸 이동 효과도 확인했습니다.

독립 코드 검토
- 중요 문제 2개를 찾고 재현 테스트가 실패하는 것을 확인한 뒤 수정했습니다.
  1. 원본 선택기가 허용하는 '기력 회복 → 금강 → 영력' 조합을 서버가 거절하던 문제.
     원본 선택 예산 방식으로 검증하며, 실제 전투의 기력 상한은 원본 판정기가 적용합니다.
     입력이 거절되면 원본 카드 선택 화면으로 돌아가 다시 제출할 수 있습니다.
  2. 준비 완료 후 캐릭터를 다시 고를 때 서버 준비 상태가 남던 문제.
     서버가 준비와 캐릭터를 비운 뒤 선택 화면을 열도록 바꿨습니다.
- 수정 뒤 전체 Node 20개와 원본 보존 3개 테스트를 다시 통과했습니다.
- 배포 폴더에서 Windows 실행기의 줄바꿈 문제를 찾아 재현 테스트 후 CRLF로 수정했습니다.
  실행기로 실제 서버를 켜고 HTTP 게임 화면이 열리는 테스트를 포함해 21개를 통과했습니다.
- 최종 배포 폴더의 포함된 실행 파일과 소스로 위 테스트를 다시 수행했습니다.
  자동 검사 21개, 보존 검사 3개, 실제 전체 경기·재대전·이탈 후 재참가,
  추가카드 1장/2장 시나리오가 모두 통과했습니다.
- 검토에서 남긴 사소한 수정 보류 항목은 없습니다.

- 정적 배포 경로의 전체 승리/캐릭터 재선택·추가카드0장/퇴장·새 참가자 접속 회귀 검사 통과.
- 링크 생성 도중 잘못된/중복 초대 주소 수신 회복과 같은 탭의 응답 링크 적용 통과. 코드 리뷰 지적 해결 후 승인.

1.2.2 STUN 직접 연결 개선
- 공개 STUN stun.cloudflare.com:3478을 ICE 설정에 추가. STUN은 주소 탐색만 하며 게임 데이터를 중계하지 않음.
- turn:/turns: 주소와 TURN 인증 정보 없음. 초대→응답 링크 교환, QR, DataChannel, 방 규칙은 유지.
- 회귀 테스트를 먼저 추가해 기존 iceServers:[]에서 실패하는 것을 확인한 뒤 구현하여 통과.
- Node 45/45, Python 7/7, 실제 두 브라우저 수동 Offer/Answer 및 IY1 호환 통과.
- 링크·QR 자동 전달, 모바일 터치 한 라운드, 전체 승리·재대전·퇴장·새 초대 검사를 통과.
- Pages용 41개 정적 파일 스테이징본에서도 전체 브라우저 경기와 STUN-only ICE 검사를 통과.
- 서로 다른 외부 PC/공유기 조합은 이 환경에서 미검증. 대칭형 NAT·CGNAT·UDP 차단에서는 여전히 실패 가능.

1.2.3 모바일 방 만들기 시간 초과 수정
- 갤럭시 S21+·5G 화면에서 확인된 "연결 코드 생성 시간이 초과되었습니다"는
  ICE 수집이 진행 중인데도 10초 고정 제한이 먼저 끝나는 경로와 일치함.
- 가상 시간 회귀 검사에서 기존 코드는 10초에 실패하고, 수정본은 20초의 완료 이벤트를 받아 코드 생성에 성공함.
- 실제 대기 한도를 30초로 늘렸으며 취소, 정상 완료, STUN-only 및 TURN 미사용 동작은 유지함.
- Node 46/46, Python 7/7, 실제 Chrome Offer/Answer, 전체 경기·재대전·교체 및 모바일 터치 링크 검사 통과.
- Pages용 41개 정적 파일에 30초 제한과 모바일 안내 문구가 포함됨을 확인함.

  Cloudflare 53 host 1 complete 미도착, Google 19302 host 1 + srflx 1 complete 미도착.
